# Operational smells

| id | Smell | Description | Attributes in tension | Candidate movements | Common false positive |
|---|---|---|---|---|---|
| `invisible-failure` | Invisible failure | Failures are caught, swallowed, or translated without preserving useful context. | clean-looking code vs. `observability`, diagnosability | Structured errors; tracing; error boundaries; metrics; dead-letter handling | A failure that's genuinely handled and recovered from, with nothing left for an operator to act on |
| `configuration-sprawl` | Configuration sprawl | Configuration is spread across code, environment variables, secrets, pipelines, and dashboards with no clear source of truth. | flexibility vs. `comprehensibility`, `operability` | Typed configuration; validation at startup; ownership; conventions; generated documentation | A small, genuinely single-source configuration that merely looks scattered because it's read from several places |
| `snowflake-runtime` | Snowflake runtime | Each environment or service needs manual steps or special-cased setup. | local optimisation vs. `operability`, repeatability | Infrastructure as code; immutable images; deterministic scripts; a golden path | A deliberately different local-dev shortcut that never runs in a real environment |
| `observability-by-accident` | Observability by accident | Logs, metrics, and traces follow no common model and don't answer real operational questions. | local speed vs. coherent `observability` | Telemetry conventions; correlation ids; operational events; question-driven dashboards | Verbose debug logging in a low-traffic area that nobody has needed to query yet |
| `unbounded-work` | Unbounded work | Jobs, queues, queries, or requests can consume unbounded resources with no explicit limit. | simplicity vs. `robustness`, `scalability` | Pagination; backpressure; quotas; timeouts; batch sizing; cancellation | Work that's unbounded in code but is provably bounded by a small, stable real-world input |
| `hidden-single-point-of-failure` | Hidden single point of failure | An apparently secondary component blocks a critical part of the system when it fails. | centralisation, simplicity vs. `resilience` | Redundancy; graceful degradation; caching; remove the central component; circuit breaker | A component that's genuinely load-bearing and acceptable as a single point of failure given its actual blast radius and cost to remove |
